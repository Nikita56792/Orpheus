# Orpheus Sync — Синхронное воспроизведение аудио и плейлистов по всему зданию

Гибридное веб-приложение (выделенный сервер `aiohttp` + Docker + локальный WebRTC P2P) для идеально синхронного воспроизведения музыки и плейлистов на телефонах, ноутбуках и Bluetooth-колонках внутри одного здания — в одной Wi-Fi сети, между разными SSID/подсетями (например, `School` ↔ `DOS-WIFI-FREE`) и при включённом VPN на устройствах.

Рабочая версия на GitHub Pages: **https://nikita56792.github.io/Orpheus/**

## Ключевые возможности
- **Гибридный сервер + локальный P2P**: мгновенное создание и вход в комнату через выделенный WebSocket-хаб (`/ws`) даже с включённым VPN на всех устройствах + автоматический фоновый апгрейд до прямого локального канала (`LAN` / `P2P UDP`) для минимального джиттера синхронизации.
- **Прогрессивный стриминг во время кэширования**: большие аудиофайлы начинают играть сразу после получения компактного стартового сегмента (< 1 сек), пока полный оригинал загружается на сервер 1 раз и параллельно кэшируется всеми устройствами с бесшовным переходом без пауз и щелчков.
- **Мгновенный Late Join**: устройства, подключившиеся уже во время воспроизведения, автоматически получают потоковый сегмент с текущей позиции, калибруют часы и встраиваются в единый звук.
- **Полностью автоматическая компенсация Bluetooth по всей сети**: каждое устройство непрерывно измеряет системную задержку (`AudioContext.outputLatency`, `baseLatency`, `getOutputTimestamp()`, `devicechange`), Хост вычисляет максимум по зданию, и все быстрые устройства автоматически выравниваются под самые медленные Bluetooth-колонки.
- **Плейлисты и живые проценты загрузки**: множественный выбор файлов, Drag & Drop, URL (CORS), встроенные тест-бит 120 BPM и метроном 1 Гц, фоновая предзагрузка следующего трека и реальные проценты загрузки (0%..100%) по каждому устройству на экране Хоста.
- **Минималистичный дизайн в стиле Apple**: автоматическое переключение светлой (`#F5F5F7`) и тёмной (`#000000`) темы по системным настройкам (`prefers-color-scheme`).

## Запуск сервера в Docker

```bash
docker compose up -d --build
```

Сервер запустится на `http://0.0.0.0:8765` (можно переопределить через переменные `PORT`, `HOST`, `MAX_FILE_MB` в `docker-compose.yml`).
Для работы с собственного домена/VPS достаточно проксировать порт `8765` через HTTPS (nginx/Caddy) — веб-интерфейс автоматически определяет свой сервер при открытии напрямую, либо его можно передать параметром `?server=https://your-domain`.
